Install in a minute

Pick your IDE. Prebuilt packages are attached to every GitHub release.

  1. Download the .vsix

    Grab llm-copilot-0.0.5.vsix from the latest release. Requires VS Code 1.74+.

  2. Install it

    Extensions view → ··· → Install from VSIX…, or from a terminal:

    code --install-extension llm-copilot-0.0.5.vsix

  3. Choose a model

    Ctrl/Cmd+Shift+P → LLM Copilot: Open Settings, then LLM Copilot: Test Connection.

Build from source instead 
git clone https://github.com/RA-King/llm-copilot.git
cd llm-copilot
npm install
npm run compile        # then press F5 for a development window
npm run package        # or build an installable .vsix (needs @vscode/vsce)

  1. Download the ZIP

    Grab llm-copilot-intellij-0.0.05.zip from the latest release. Requires IntelliJ IDEA 2026.1+ (Community or Ultimate).

  2. Install from disk

    Settings → Plugins → ⚙ → Install Plugin from Disk…, pick the ZIP, restart the IDE.

  3. Choose a model

    Settings → Tools → LLM Copilot, then run LLM Copilot: Test Connection.

Build from source instead 
git clone https://github.com/RA-King/llm-copilot-intellij
cd llm-copilot-intellij
chmod +x gradlew
./gradlew buildPlugin
# → build/distributions/llm-copilot-intellij-0.0.05.zip

The build compiles against your local IntelliJ install and runs Gradle on a JDK 21 it finds for you — your system JDK is left alone.

How to use it

A tour of the everyday workflows.

01

Just type

When you start a new line, a declaration keyword or a fresh statement, a grey suggestion appears. The plugin reads what the enclosing function is working towards — collectActiveNames accumulates, validateEmail checks and rejects — and asks the model to continue that thought.

  • Tab to accept, Esc to dismiss
  • Ctrl/Cmd+Shift+Space to ask on demand
  • Turn off auto-trigger with llmCopilot.autoTrigger: false
02

Ask inline

Put the cursor in the editor — optionally select some code — press Ctrl/Cmd+I and describe the change: “convert this to async/await”, “add null checks”. The edit is applied in place. For longer conversations, open the chat panel with Ctrl+Alt+I.

03

Get unstuck on errors

When a terminal command fails or the debugger stops on an exception, press Ctrl+Alt+E (or right-click the output). You get a short list of candidate fixes — each with the file and line it edits and how sure the model is — written against the real declarations, callers and manifest from the project index.

  • Work it through properly for a full diagnosis
  • Jump straight to the failing file, or any file a fix names
  • Java, Kotlin, Python, Node, Go, Rust, C#, Ruby, PHP and build-tool failures
04

Act on a selection

Select code and press Ctrl+Space for the actions menu, or go straight to one: explain, fix, refactor, generate unit tests. Put the cursor inside a class to scaffold a constructor, accessors or interface methods. Stage your changes and press Ctrl/Cmd+Shift+M for a Conventional Commits message.

05

Let it learn the codebase

On open, every source file is read in the background into a symbol table, a two-way import graph and a digest of the project's shape. Nothing waits for it, and later sessions only re-read files that changed. Check on it with LLM Copilot: Show Project Index Status.

settings.json
{
  "llmCopilot.projectIndex.enabled": true,
  "llmCopilot.projectIndex.maxFiles": 4000,
  "llmCopilot.projectIndex.maxFileSizeKb": 256,
  "llmCopilot.projectIndex.exclude": ["**/generated/**"],
  "llmCopilot.projectIndex.completionBudgetChars": 2400
}

Troubleshooting

No suggestions appear

Run LLM Copilot: Test Connection. Check completions are enabled, the provider and model are spelled the way the provider expects, and — for hosted providers — that an API key is set.

“Connection refused” with Ollama or LM Studio

Make sure the local server is running and the base URL matches its port: 11434 for Ollama, 1234 for LM Studio.

Changing the base URL does nothing

Expected for hosted providers — their endpoints are fixed. The base URL only applies to Ollama, LM Studio, Azure, Claude Code and Custom.

The Claude Code proxy isn't found

Run LLM Copilot: Diagnose Claude Code Connection (VS Code) or Test Connection (IntelliJ) to see which port and path answered, then set them explicitly.

Completions feel laggy or too eager

Adjust the debounce, or turn auto-trigger off and ask on demand with Ctrl/Cmd+Shift+Space. Show Project Index Status reports the latency it has measured.

Where are my API keys stored?

In VS Code settings, and in IntelliJ's plugin settings file (LLMCopilot.xml) as plain text. Prefer a local provider on shared machines.
